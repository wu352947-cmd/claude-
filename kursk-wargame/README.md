# 库尔斯克 1943 · 全线战役兵棋（项目设计文档）

> 工作名：**《堡垒与鲁缅采夫：库尔斯克 1943》**
> 类型：作战级（Operational）六角格兵棋，数字版为主、可打印桌面版为辅
> 时间范围：1943-07-04（堡垒行动前哨战）至 1943-08-23（哈尔科夫解放）
> 设计取向：**追求"历史可能性"与推演价值，不追求对称平衡**

本目录是这个项目的**设计与规划文档**，还没有任何游戏代码。读完它，你应该能回答：
做什么、做到什么程度算对、按什么顺序做、用什么工具做、去哪里找史料、怎么证明自己"还原得对"。

## 一页纸结论（关键决策）

1. **用 vibe coding 开发：你做设计、考据和验收，AI 写代码。** 用 AI 写代码后，数字原型和纸面原型一样便宜，所以直接做可在网页上玩的原型；但兵棋的乐趣与历史性 80% 在规则和数据里，这部分必须你亲自把关。执行方案见 [07](docs/07-Vibe-Coding开发流程.md)。
2. **最小可行版本 = 南线（堡垒行动南翼，7 月 4–17 日）。** 原因：这是史料最细的一段——杜普伊研究所的《库尔斯克数据库》（Kursk Data Base, KDB）有双方逐日、逐师的兵力与损失，可以拿来**定量校准**你的战斗系统。北线、库图佐夫、鲁缅采夫行动依次扩展，最后合成全线战役。
3. **比例尺建议：每格约 3 km，单位为团/旅（苏军步兵为师），每天 3 回合（上午/下午/夜间）。** 能同时表现普肖尔河、佩纳河、冲沟（балка）这些决定性地形，又装得下从奥廖尔到哈尔科夫的大纵深机动。最终数值要在纸面原型里验证。
4. **技术路径：TypeScript 规则引擎（纯逻辑、确定性、可回放）+ PixiJS 渲染 + React 界面，浏览器运行，以后用 Tauri 打包桌面版/上 Steam。** 发个链接朋友就能玩；同一个引擎可以在 Node 里无界面跑上千局做历史校准。
5. **联机先做"热座 + 邮件战（PBEM）"，AI 放到后面。** 作战级兵棋的 AI 是最难、最耗时的部分；你说想和身边同好分享——人对人正是兵棋最好的玩法。
6. **地图从史料开始，而不是从卫星图开始。** 1940 年代苏军总参谋部 1:100,000 地形图 + 德军翻印图 + 高程数据，在 QGIS 里配准、矢量化，再由脚本自动生成六角格地形，人工复核。现代地图会骗你（例如别尔哥罗德水库 1985 年才建成）。
7. **每一个数字都要有出处。** 单位数据表里每行带"来源 + 页码 + 可信度等级"，史料之间矛盾时写进争议登记表，并决定采用哪一说、为什么。
8. **"历史可能性"的检验标准：** 按历史命令自动推演上千次，真实历史结果应落在模拟结果分布的主体区间（例如 25%–75% 分位）内，而不是平均值必须等于历史，也不能落在极端尾部。

## 推荐的第一周（vibe coding 版）

- [ ] 把 [07 §5](docs/07-Vibe-Coding开发流程.md) 里"冲刺 0 的开场提示词"发给 AI，拿到在线预览链接
- [ ] 依次完成冲刺 1、2：看到自己的六角格地图和算子

同时并行（这些 AI 替代不了）：


- [ ] 读 Glantz & House《The Battle of Kursk》或 Töppel《Kursk 1943》任意一本，建立全局图景
- [ ] 买/借一款同类成熟兵棋实际推一遍（推荐 GMT《Ukraine '43》——正好从库尔斯克战役之后的别尔哥罗德-哈尔科夫进攻开始；或你图里的《Holland '44》）
- [ ] 安装 QGIS，找到一张别尔哥罗德—普罗霍罗夫卡地区的 1940 年代地形图，试着配准
- [ ] 按 [templates/](templates/) 的格式，录入第 2 SS 装甲军三个师 7 月 4 日的坦克数量，每个数字都写上出处
