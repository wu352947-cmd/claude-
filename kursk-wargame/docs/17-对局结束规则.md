# 17 · 对局结束规则

> 状态：AI 提出、所有者同意方向（"1+2+软时限"）；数值是设计参数，待试玩校准。

## 为什么改
想定原先硬性打满 9 回合就结束。所有者希望"像指挥官一样自然推演"：不被死板的回合数卡住。

## 现在的规则（想定里的 `end` 段，`engine/end-rules.ts`）
1. **随时收兵**：行动方点"收兵"（指令 `Conclude`），当场结束，按现状判胜负。界面有确认框。
2. **提前分出胜负**：一方连续 `holdTurns`（S1 = 2）个回合末都处于"达成战争目标"的结果（`victory` 里 winner 非空），并且已到 `minTurn`（S1 = 6），对局结束。
   - 为什么要 `minTurn`：守方开局就占着全部目标，不设下限会在第 2 回合就判苏军胜。
3. **软时限**：到想定的 `turns`（S1 = 9）只提示一次（事件 `TimeLimit`、状态 `limitReached`），可以继续打。
4. **硬上限**：`hardTurns`（S1 = 27）强制结束，防止电脑对打或挂机永远不结束。
5. 想定没有 `end` 段：仍是打满 `turns` 回合就结束（旧行为，其他想定、旧测试不受影响）。

## 没做 / 要注意
- **没有加"拖得越久对德军越不利"的因素**（补给、后续兵力）。想定的增援表只到第 9 回合，之后没有新增援；不循环、不编数字，需要史料再补。
- 软时限之后日夜节奏照常循环（上午/下午/夜间）；日期继续往后算。
- 对局模拟（`npm run sim/matrix`）以"提前结束或到软时限"为止，所以各组打法的结果口径与以前一致，只是可能提早结束。
- 电脑不会主动收兵；打不动时只会不断结束阶段，直到分出胜负或到硬上限。
