# 07 · Vibe Coding 开发流程（本项目的执行方案）

> 本文**取代** [04-开发流程与里程碑](04-开发流程与里程碑.md) 中"新手学习路径"与"先纸面后数字"的安排。04 中的阶段目标、完成标准、风险清单仍然有效。

## 1. 分工：你是设计师、史学考据和测试员，AI 是程序员

| 你负责 | AI 负责 |
|---|---|
| 说清楚"要什么"：规则、手感、历史现象 | 写代码、写测试、跑测试、修 bug |
| 史料考据与每一个历史数字 | 把你给的史料整理成数据文件（**不编造数字**）|
| 亲手玩、找出"不像历史/不好玩"的地方 | 根据你的反馈改规则参数或代码 |
| 决定取舍（规则复杂度、想定范围） | 给出方案和利弊，让你选 |
| 每次验收后决定"保留/回退" | 提交到 git，保证随时可以回退 |

**代码由 AI 写，但规则和史料必须由你把关**——这是这个项目和"随便让 AI 做个游戏"的根本区别。

## 2. 这样做为什么可行：护栏

Vibe coding 最大的风险是越改越乱、改一处坏三处、AI 编造历史数据。本项目用五道护栏防住：

1. **项目规则文件 [`CLAUDE.md`](../CLAUDE.md)**：AI 每次开工都会读它。里面写死了架构原则（规则引擎与画面分离、确定性随机数、数据驱动）、史料纪律（禁止编造历史数字）、测试要求。
2. **规则引擎有自动化测试**：每加一条规则，AI 必须同时写测试；每次改动后全部测试必须通过。你不用看懂代码，只要看到"测试全绿"。
3. **规则数值放在数据文件里**（JSON），不写死在代码里：调平衡、改 CRT、改移动消耗时，你可以直接说"把开阔地的装甲修正从 +1 改成 +2"，甚至自己改。
4. **小步提交 + 分支**：一次只做一件事，做完你验收再提交；搞砸了一句"回退到上一个版本"就行。
5. **在线预览链接**：每次推送自动部署到网页，你和朋友用手机/电脑直接打开验收。

## 4. 每一轮的工作循环（一轮 = 一个小功能，约 0.5–2 小时）

```
① 你描述需求（用下面的模板）
② AI 先复述理解并给出计划 ——你确认或纠正
③ AI 实现 + 写测试 + 跑测试
④ AI 汇报：改了什么、测试结果、需要你怎么验收
⑤ 你打开预览链接亲手玩，按验收清单检查
⑥ 通过 → 让 AI 提交推送；不通过 → 描述现象（截图最好），回到 ③
⑦ 在 DEVLOG.md 记一行：做了什么、决定了什么
```

### 需求模板（复制使用）

```
【目标】我想要……（一句话）
【历史/设计理由】这是为了表现……（可选，但对规则类需求很重要）
【具体规则】1. … 2. … 3. …
【不要做】…（防止 AI 自作主张扩大范围）
【验收】我会这样检查：……
```

### 反馈的写法

- ✅ 好："德军装甲团在开阔地攻击苏军步兵师，赔率 3:1，结果显示攻方损失 2 步——应该很少出现，请检查 CRT 第 3:1 列"
- ❌ 差："战斗不对"

## 5. 冲刺计划（按顺序，每个冲刺结束都有能玩/能看的东西）

| # | 冲刺 | 你会看到的成果 | 验收要点 |

## 6. 史料数据怎么"vibe"

- **你**读书、做笔记（拍照、手打都行），注明书名和页码。
- **AI** 把笔记整理成 `sources.csv`、单位 JSON，并**标出缺失和矛盾**。
- **你**逐条核对 AI 整理的数字与原书——AI 抄错、串行是常见问题。
- AI **不得**凭记忆补历史数字。需要数字但还没考据的地方，用占位值并标 `"confidence": "placeholder"`；游戏里占位数据显示为灰色斜体，提醒你还没核实。
- 冲刺 7 的 S1 可以先用占位数据把机制跑通，**M1 之后**再逐步换成考据过的数据。

## 7. 常见坑与对策

| 现象 | 对策 |
|---|---|
| AI 说"完成了"但其实有 bug | 要求它跑测试并贴结果；你按验收清单亲手玩 |
| 改一个地方坏了别的 | 让 AI 先补一个能复现问题的测试，再修 |
| 越聊越乱、AI 忘了前面的约定 | 开新对话，让它重新读 CLAUDE.md 和 DEVLOG.md；重要约定写进 CLAUDE.md |
| 一次要的太多，结果一团糟 | 拆小：一轮只做一个功能；回退到上个提交重来 |
| 文件越写越大 | 让 AI 按模块拆分（movement.ts、combat.ts…），单文件尽量 < 400 行 |
| 规则改来改去忘了为什么 | 每个规则决定记进 DEVLOG.md 和设计文档 |
| 游戏卡顿 | 描述"在哪个操作、多少单位时卡"，让 AI 做性能分析 |
| 不知道 AI 写的东西对不对 | 让它"用不懂编程的人能听懂的话"解释，并给一个能在游戏里看到效果的例子 |

## 8. 纸面原型还要不要做？

可以不做独立的纸面原型——数字原型对 vibe coding 来说同样便宜。但建议保留两件事：
- 冲刺 7 之后，让 AI 加一个"导出打印版地图与算子 PDF"的功能，和线下朋友面对面推一局，桌面讨论的反馈质量往往更高。
- 规则书（Markdown）与代码同步维护：规则书是给人看的"需求"，代码按规则书实现，测试按规则书举例写。
